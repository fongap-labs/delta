# ADR-0067：本地资料库与全文检索

状态：**提议**（实现按所有者 2026-10-25 对路线图任务 B1 的批准进行；待所有者确认后改为"已接受"）。

## 背景

路线图 B1 要求：用户授权的目录建立本地索引（SQLite FTS5 起步，可选 Ollama 向量），检索结果带可验证的出处，索引版本写入账本，`private_only` 下索引零出站。

撰写时的现状（已核对）：模型只能逐个文件读取（`read_file`、`read_document`）或搜索网页；没有"在我自己的文件里找"的能力。`rusqlite` 已随 `bundled` 带有 FTS5，不需要新依赖。

## 决定

### 1. 范围：全文索引，不含向量层

- **只做 FTS5 全文检索。** 没有嵌入模型、没有任何网络请求，因此任何出站档位（包括 `private_only`）都不受影响，不需要出站判定。
- **可选的向量（语义）层不在本次范围。** 它需要用户配置嵌入服务，并按 ADR-0057 判定去向；单独决定。

### 2. 索引什么

用户在设置 ▸ 资料库里选定的文件夹，或模型经批准调用 `library_index` 指定的、本会话有权读取的文件夹。读取：txt、md、csv、tsv、json、yaml、html、rst、log，以及 PDF、DOCX、XLSX、PPTX（复用 `read_document` 的解析）。

- 不跟随符号链接；跳过隐藏文件与隐藏文件夹、`node_modules`、`target`、`dist`、`build`、`venv`、`__pycache__`、`site-packages`；大于 25 MB 的文件、读不了的文件和没有文字的文件记为"跳过"并写明原因，不算失败。
- 非 UTF-8 的文本按 GBK 解码；HTML 用已有的隐藏文字过滤（B6），隐藏内容不进索引。
- 每个文件切成约 800 字符的片段，每个片段带位置：文本与 HTML 是行号范围，PDF 是页，DOCX 是第几部分，XLSX 是工作表和行范围，PPTX 是第几张幻灯片。位置用 `source_citation` 的 `lines`、`page`、`row`、`custom` 词汇，可以直接引用。一个文件最多 4000 个片段。

### 3. 怎么搜

- 分词用 `trigram`：任何语言中连续 3 个及以上字符都能匹配，中文也可以；不区分大小写。
- 少于 3 个字符的词（如"审核"）不能用三元组索引，改为对片段做子串扫描，结果同样返回。
- 多个词必须都出现。查询里的引号、`OR`、`NEAR`、`*`、括号等一律当作普通文字，不会改变检索语法。
- 同一文件在一次回答里最多 3 条，避免一个长文件挤掉其他文件。
- **范围由权限决定，不由索引决定。** 搜索只在本会话有权读取的文件夹内进行；其他已索引文件夹的内容不会出现。尚未索引的文件夹列在 `not_indexed` 里。

### 4. 出处可验证

每条命中返回：文件路径（相对文件夹）、位置、片段、**索引时的 SHA-256**、索引版本，以及 `stale`——文件的大小或修改时间与索引时不同，或文件已不存在。**片段只是线索**：工具说明要求模型引用前先用 `read_file` 或 `read_document` 读原文（这一步会按现有机制记录 `source.read`，带指纹），引用时写明路径和位置。

### 5. 增量与版本

- 再次索引只重读变化的文件：大小和修改时间都没变就不读；变了就算 SHA-256，内容没变只更新时间，不算新版本。
- 每个文件夹有一个索引版本，只在有文件被重读、移除或跳过时加一。
- 只有看完整个文件夹的一次运行才会把磁盘上已不存在的文件移出索引；超时或取消的运行不会误删，下次继续。
- 单次运行有时间预算（模型工具 5 分钟，设置页 30 分钟），到点干净地停下并报告 `is_complete: false`。
- 每次运行结束向账本的 `$source` 流追加 `source.indexed` 事件（文件夹、版本、各项计数）。**权威是资料库自己的版本号**；账本事件是"索引动过"的记录。

### 6. 工具与权限

- `library_search`：只读，不需要批准，副作用 `read`。
- `library_index`：副作用 `local_write`（写资料库数据库，不写工作区），中等风险，需要批准。参数叫 `folder`，不叫 `path`，因为能力主机会把 `path` 当作要先哈希的输入文件。
- 两个工具都不是出站工具（没有 `destination`，不属于受管控类别），`egress::outbound_target` 对它们返回无目标。
- 资料库数据库 `library.db` 在状态目录，不在工作区里，不会被打包或同步。

## 后果

- 新增 `retrieval` 模块（`Library`、抽取与切片、两个工具）、`CoreControlPlane` 的 `library_roots/index/remove`、Tauri 命令 `library_roots`、`library_index`、`library_remove`、设置 ▸ 资料库。
- 系统提示词增加一句：在用户自己的文件里找东西用 `library_search`，命中先读原文再引用。

## 未验证事项

- **量级测量。** 10,000 个文件（每个约 2.3 KB、共 40,000 个片段）的合成目录，在 release 构建下索引用时约 3.5 秒，一次检索约 3 毫秒（`cargo test ten_thousand --release -- --ignored`）。这不是真实文档：真实的 PDF、DOCX 解析会慢得多，路线图的"10 分钟内"只对这个合成负载实测过。
- 没有测过 PDF 的索引（仓库里没有 PDF 样例，也没有 PDF 写入器）；PDF 走的是 `read_document` 的同一解析器。
- Tauri 命令在本次开发环境无法编译，仅按同文件中同类命令对照写成。
- 设置页的索引没有进度条，只有"正在索引"提示；模型工具会发进度事件。
- 没有做文件系统监听：文件夹变了需要再次索引，搜索结果会用 `stale` 提醒。
- 向量层未做（见决定 1）。
