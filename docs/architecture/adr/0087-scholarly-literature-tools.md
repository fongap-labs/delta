# ADR-0087：学术文献工具（检索、记录、核验引文）

状态：**已采用，待联网验证**（2026-10-28，按所有者要求参考 `dsh-ai4scholar` 或更优思路）。承接 ADR-0058、ADR-0061、ADR-0069，不改变它们的审批与出境规则。

## 背景

研究分析需要找文献、读文献、写引文。现状（已核对代码，并非假设）：

1. Delta 只有通用的 `web_search` 与 `web_fetch`（ADR-0069）。`web_fetch` 已能读网上的 PDF，但找论文要靠通用搜索引擎，结果是网页而不是论文记录，没有引用关系、没有引用次数、没有免费全文的地址。
2. 模型写参考文献时靠记忆，容易编出不存在的论文或 DOI。这与 Delta 其他地方"数字必须可追溯"（`report_check`）的做法不一致。
3. 仓库中没有任何对 `dsh-ai4scholar` 的引用。

### 被参考的对象：dsh-ai4scholar

`dsh-ai4scholar` 是 DeepSeek Harness（dsh）的学术文献插件，MIT 许可，提供 38 个工具：Semantic Scholar（17 个）、PubMed（5 个）、Google Scholar（1 个）、arXiv（3 个）、bioRxiv/medRxiv（6 个）、按 DOI 下载与阅读（2 个）、自动插入引文与科学绘图（2 个）、余额查询（1 个），另有一个合并多个来源并去重的 `search_papers`。

值得借鉴的做法：

- 一个统一的检索入口，按 DOI、arXiv 编号、PMID 或标题去重。
- 引用关系（引用了谁、被谁引用）和相似论文推荐。
- 长全文分块读取，避免撑爆上下文。
- 一段系统提示词，告诉模型什么任务用哪个来源、怎样按 DOI 引用。

不直接采用的原因：

- **付费中转。** 除 arXiv、bioRxiv/medRxiv 和 DOI 工具外，Semantic Scholar、PubMed、Google Scholar 都经 `ai4scholar.net` 按积分计费，查询内容发往这家第三方服务，其留存策略页面没有说明。这与 ADR-0057、ADR-0061 的出境约束冲突：用户无法在 Delta 里判断一条查询发给了谁。
- **工具太多。** 38 个工具定义会占用每一轮请求；Delta 对可选工具的原则是只提供会话用得上的（`tool_surface.rs`）。
- **引文不核验。** `auto_cite` 按积分收费，页面也没有说明是否核对记录是否真实存在。

## 决定

### 1. 三个工具，直连开放来源

| 工具 | 作用 |
|---|---|
| `scholar_search` | 检索文献：标题、作者、年份、期刊、DOI、被引次数、摘要片段、免费全文地址。可按年份范围限定，可按被引次数排序。 |
| `scholar_paper` | 读一篇论文的记录：摘要、它引用的一部分文献、引用它的一部分文献（被引最多的在前）。可用 DOI、`arXiv:编号`、`PMID:编号` 或 OpenAlex 编号指定。 |
| `scholar_cite` | 核验并生成引文：对每条参考文献查记录，按 `bibtex`、`apa` 或 `gbt7714` 写出引文，并报告 `found` 与 `title_matches`。 |

数据来自两个无需账号的开放服务：

- **OpenAlex**：检索、摘要、引用关系、开放获取全文地址，也涵盖 arXiv、PubMed 的条目。
- **Crossref**：出版方登记的 DOI 记录，用于核验与格式化。Crossref 没有的 DOI（例如 arXiv 自己登记的）由 OpenAlex 回答。

全文不新增下载工具：`scholar_paper` 返回 `open_access_url`，模型用现有的 `web_fetch` 读取，PDF 与分块续读已由 ADR-0069 解决。

### 2. 引文由工具写，不由模型写

- `scholar_cite` 从记录生成引文，是确定性的字符串格式化，没有模型参与，也没有额外费用。
- 模型把想引用的标题一并传入时，工具比较标题与记录是否一致（忽略大小写与标点；一方是另一方的前缀且不少于 12 个字符时也算一致，以容许省略副标题）。真实的 DOI 配上不符的标题，返回 `title_matches: false`。
- 没有记录支撑的参考文献返回 `found: false`，**不生成引文**。提示词要求模型不引用这样的文献，并告诉用户。
- 提示词同时要求：只读了摘要时要说明只读了摘要。

### 3. 出境

- 三个工具属于 `web` 类别，风险为中、需要审批，目的地类别声明为 `any_public`。原因：策略的 `fixed_public` 声明只带一个固定地址，而这里有两个主机；按公共目的地处理意味着总是询问，出境档位与每路径规则都适用，更保守。
- 授权的网络范围只写这两个服务，模型不能指定其他主机。
- 三个工具在出境规则中共用一个路径 `scholar`，用户可以只对文献检索设规则。这正是 ADR-0061 提到的情形：机密数据的工作区里，有意地放行公开文献检索。隐私设置页的"每个工具的规则"中新增"学术文献"一行。
- 策略把三个工具列入出境工具（`EGRESS_TOOLS`），风险下限为 L3。

### 4. 提示词

文献工具的使用指引只在会话提供这些工具时才出现在系统提示词里（提示词按已提供的工具分块，见 `agent.rs`）。工具被出境档位拒绝时，工具与指引一起消失。

### 5. 引文进入报告：与数字同一道门禁

ADR-0055、ADR-0079 已规定报告里的数字只能是对结果文件的绑定。文献论断用同一思路：

- `scholar_cite` 带 `output_path` 时，把每条参考文献及其核验结果写成 `delta.references` v1 文件（`found`、`title_matches`、来源、引文文本、核验日期）。
- Markdown 模板用 `{{cite:<文件>#<编号>}}` 写引用，用 `{{references:<文件>}}` 放参考文献列表。`report_render` 把前者变成按首次引用顺序编号的 `[n]`，把后者变成所引文献的列表；清单文件、编号与引文文本都记入绑定清单（`<报告>.bindings.json`，条目带 `kind: "cite"` 或 `"references"`）。
- **没有记录支撑的参考文献不能渲染**：`found` 为假、标题与记录不符、文件里没有该条目，都会让整份报告不被写出。
- `report_check` 重新读取参考文献文件：文件的 SHA-256 必须没变；每条被引用的文献必须仍然有记录支撑；参考文献列表必须与文件一致；标记的位置与文本必须与清单一致，手工改动会被发现。正式报告里，标记与列表占用的字符不算"清单之外的数字"，其余未绑定的数字仍会被列出。
- 这是确定性的本地检查，检查时不联网。它保证"报告里的每条引用都曾被核验过并且没有被改动"，不保证论断本身与论文内容相符：那需要读论文，仍由人和模型判断。
- 参考文献文件的字段是新增的合同；旧版本的检查器读到 `kind` 字段的条目会报告条目不完整。

## 不做

- **Semantic Scholar、PubMed、Google Scholar 的直连。** OpenAlex 已涵盖其条目与引用关系；Google Scholar 没有开放接口。需要时再按同一模式增加来源，不预先增加工具。
- **预印本全文的专用下载工具。** `web_fetch` 已能读 PDF。
- **自动把引文插入文档、科学绘图。** 引文由 `scholar_cite` 给出，写入文档走现有的文档工具；绘图不属于文献检索。
- **付费或带账号的服务。** 本 ADR 的来源都不需要账号或密钥。

## 后果

- 三个工具不受 `tool_surface.rs` 的会话事实限制，始终提供（文献检索不依赖工作区里已有的东西），默认提供的工具增加 3 个（约 3 KB 定义），换来：研究类任务不再靠通用搜索找论文，引文有记录支撑。
- 提示词多一个仅在这些工具提供时出现的指引块。
- 引文格式目前只有三种：BibTeX、APA、GB/T 7714。作者姓名按"最后一个词是姓"拆分（OpenAlex 只给显示名），复姓或带连字符的姓可能拆错；有 Crossref 记录时用 Crossref 的结构化姓名，不受此影响。

## 未验证事项

- **开发环境没有对 OpenAlex 与 Crossref 发过真实请求。** 请求与解析按两个服务的公开文档编写，并用样本响应与本地测试服务器验证。真实响应的字段、速率限制和错误形态需要联网后抽样检查。
- **OpenAlex 可能要求（免费）密钥。** 若如此，需要在设置里增加一个可选密钥，并通过凭据存储授予工具；目前没有。
- **`filter=openalex:W1|W2` 与 `filter=cites:W…`** 的语义来自公开文档，未实测。
- **未加 Crossref 的礼貌池参数（`mailto`）。** 这需要用户的邮箱，不能默认带上；被限速时工具返回"正在限速，请稍后再试"。
- 引文格式用样本核对了字段顺序，没有对照完整的 GB/T 7714-2015 与 APA 7 例表逐种文献类型核对，期刊文章之外的类型（会议、图书、其他）只做了基础处理。
