# ADR-0089：撤销一次请求写入的文件

状态：**已采用**（2026-10-28，按所有者要求参考 DeepSeek Harness 社区插件 `dsh-checkpoint-rewind`：改文件前快照，需要时回退）。承接 ADR-0053（运行身份）。

## 背景

- 现状（已核对代码）：通过产物路径写入的文件（`write_file`、`create_document`、`edit_document`、`report_render` 等）在**替换**已有文件时，旧版本会被移到 `.delta/versions/<run>/<路径>`（同一次运行里第一次替换保留原件），交付卡片上每个被替换的文件有"还原旧版本"。
- 缺口：
  1. 一次请求写了好几个文件时，只能逐个还原。
  2. 请求**新建**的文件没有撤回的办法。
  3. 对不熟悉版本管理的办公用户，"这次请求我不要了"是常见需求。
- `dsh-checkpoint-rewind` 用 Git 在改文件前做快照。Delta 不引入对 Git 的依赖，也不需要新的快照：运行已经保留了被替换的原件，产物登记（账本里的 `artifact.registered`）已经记录了每次运行写了哪些文件以及写完后的 SHA-256。

## 决定

### 1. 一个核心操作：`undo_run_files(会话, 运行)`

- 取这次运行在账本里登记的全部产物，同一路径取最后一条记录（它的 SHA-256 是运行留在那里的内容）。
- 对每个文件，**只有当它现在仍然与运行写完时一模一样（SHA-256 相同）才动它**：
  - 运行保留了被它替换的原件（`.delta/versions/<run>/<路径>` 存在）→ 当前文件复制到 `.delta/versions/undone-<时间>/<路径>`，原件写回。
  - 否则是运行新建的 → 当前文件移到 `.delta/versions/undone-<时间>/<路径>`，从工作区取出。
- 之后被用户或后续运行改过的文件（SHA-256 不同）、已被删除的文件、保留路径，一律**不动**并在结果里列出原因（`changed_since`、`missing`、`reserved`）。
- 不删除任何东西：撤销掉的内容保存在 `.delta/versions/undone-<时间>/`，随 `KEPT_VERSION_DAYS` 一起过期清理。因此撤销本身也能手工撤销。
- 再点一次是安全的：撤销后文件不再与记录相同，会被当作"之后被改动"跳过。
- 运行必须属于该会话（消息里记录的 `run_id`），否则拒绝。

### 2. 界面

- 交付卡片（一次请求结束后列出它写的文件的那张卡片）增加"撤销这些文件改动"。点击后先确认（它会取出请求新建的文件），再执行，并说明"恢复几个、移出几个、几个因为之后被改动而保持原样"。
- 请求仍在运行时、没有文件时、或没有记录到运行编号时不提供。
- 运行编号取自请求的用户消息（`run_id`）。一次请求如果因恢复而跨了多次运行，只撤销该用户消息对应的那次运行。

## 不做

- **不追踪 `run_shell` 写的文件。** 命令行产生的文件不是登记的产物，Delta 无法知道它改了什么。要覆盖它，需要在每次执行命令前对工作区做快照，成本与空间都不可控，先不做。`run_shell` 本来就需要审批。
- **不在对话回退时自动撤销文件。** "编辑消息"与"重新生成"只回退对话，不碰文件；撤销文件是单独的、需要确认的动作。
- **不做逐文件之外的选择性撤销。** 需要单个文件时，仍用卡片上每个文件的"还原旧版本"。
- **不引入 Git。**

## 未验证事项

- 只用手工构造的账本与工作区测试，没有在真实的多步骤请求（连续写同一文件、跨运行恢复）上验证。
- 工作区位于网络盘或被其他程序占用时，`rename` 失败会退回复制再删除；占用中的文件可能删除失败，此时撤销会在该文件处返回错误。
