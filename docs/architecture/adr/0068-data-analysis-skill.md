# ADR-0068：随产品发布的统计分析技能，以及移植时"已有则择优"的取舍

状态：**已接受**（所有者，2026-10-26）。

## 背景

能力移植任务要把外部产品（WorkBuddy 等）的办公与数据分析能力带进 Delta。所有者的要求是：已有功能先对比，择优留用。撰写时的现状（已核对）：

1. **办公文档。** 系统提示（`agent.rs`）已规定：用 `read_document` 读，用 `create_document` 新建，改已有文件用 `edit_document` 而不是重建，先读后改并说明改了什么。三个工具的说明里写明了各格式的结构、回读校验和"只做结构、不做版式"。
2. **统计分析。** 系统提示已规定主流程：不自己算数；要进报告的数字用 `statistics_record`；用 `report_render` 写报告，用 `report_check` 核对；R 不可用就停。
3. 对比外部移植来的"Python 脚本 + pandas/matplotlib"方案：桌面应用不随附 Python（ADR-0058），可报告的数字必须由 R 计算（ADR-0054）并可追溯（ADR-0055）。pandas 算出的数字进不了正式报告。

## 决定

### 1. 办公文档：保留现状，不新增技能

系统提示加工具说明已经覆盖选工具、先读后改和校验。再加一个 `office-documents` 技能只会重复，还多一次按需加载。**不新增。**

### 2. 统计分析：只补现状里没有的内容

新增内置技能 `data-analysis`（机制同 ADR-0066：编译进二进制，只读，可关闭，可复制，只有指令，不声明权限）。它**不重复**系统提示里的主流程，只写以下现状没有的内容：

- 按问题选工具的对照表（含各方法需要的参数）；
- 报告模板示例，以及键的写法（`groups.1.mean`、`coefficients.2.estimate`）；
- 正式报告里"任何阿拉伯数字都算未绑定数字"带来的实际陷阱（"p 小于 0.05"、"95%"、版本号、列名里的数字），以及绑定 `conf_level` 或用 `allow` 的办法；
- `%.4f` 会把很小的 p 值显示成 0.0000；
- 哪些数字不能绑定（`statistics_describe`、`statistics_doe` 不写结果文件；文字；空值），遇到时怎么如实处理；
- 如实说明做不到的事：不能生成图表，不检验统计前提，R 不可用就停，报告只支持 Markdown。

系统提示的技能提示句里加入"统计报告"，使模型会去 `find_skill`。

### 3. 技能里的说法由测试固定

- 技能点名的每个工具都必须是产品注册的工具；
- 技能里的模板能被 `report_render` 渲染，并通过正式模式的 `report_check`；
- "字面数字使正式核对失败"和"%.4f 显示 0.0000"两条说法各有一个测试。

## 不做

- **图表。** `create_document` 没有图表块，技能如实说明。图表能力需要另做方案（Rust 原生渲染，或引入 Worker 依赖），本 ADR 不决定。
- **v1 的 `analyze.py`。** 不入库（理由见"背景"第 3 点）。

## 已发现、未处理的缺口

- `statistics_record` 不支持 `statistics_describe`（单列的 n、均值、标准差、中位数）与 `statistics_doe`，所以这些数字无法绑定进可核对的报告。ADR-0055 已把它列为未实现。给 `statistics_record` 增加 `describe` 是一个小的 Rust 改动，建议另做。

## 后果

- 内置技能由 3 个变为 4 个；`find_skill` 对含 "report" 的查询也会返回 `data-analysis`，排在用户自己的同名匹配之后。
- 系统提示的技能提示句多了一个片段。

## 未验证事项

- **没有用真实模型端到端跑过。** 已验证的是：`find_skill` 能用中英文找到它；技能点名的工具都存在；技能里的模板能渲染并通过核对；陷阱说法与代码行为一致。模型是否因此写出更好的报告，需要在装有 R 4.6.0 的机器上用真实模型试跑；试跑没有改善就删除这个技能。
- 开发环境没有 R，所以没有真实调用 `statistics_record`；模板测试用手工构造的结果文件，其键来自 `statistics_record` 的展平规则。
