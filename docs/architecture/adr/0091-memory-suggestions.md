# ADR-0091：记忆的保存——由模型建议、由用户决定（第一步）

状态：**已采用，分步实现**（2026-10-28，按所有者要求先做最小范围）。第一步只做"建议—确认—保存"，**不把记忆交给模型使用**；注入与检索留到后续步骤。本文由原先编号 0087 的草案改写，原草案中的注入与嵌入检索部分保留为"后续步骤"。

## 背景

- `crates/delta-core/src/memory.rs` 原来是一张扁平的 `memories` 表：更新原地覆盖，没有来源，记忆页写明"未开启，不发送给模型"，开关不可用。界面里留有 `memory_saved` 事件的处理，但运行时从不发出它，所以对话里没有任何保存记忆的路径。
- 蓝图第 7 节规定学习闭环，并规定学习不能自动修改权威、策略与出境边界。
- Delta Foundation 拥有唯一的权威平面：记忆只能在 Delta 内部实现，不引入外部的第二个记忆权威。
- ADR 由本批改动（提示词与请求体量）形成的约束：系统提示词与工具定义每轮不变，才能被模型服务商缓存。

## 决定

### 1. 模型只能建议，用户决定

- 新增模型工具 `memory_propose(content, evidence?)`：提出一条值得长期记住的事实，可附上用户自己的话作为依据。**它只在候选表里新增一行，不产生任何记忆。**
- 候选带来源：会话编号、运行编号与那句引文。候选不得影响权威、策略、审批或出境边界。
- 用户在两处决定：对话里紧跟该次调用出现的建议卡（记住 / 修改 / 不用了），以及"设置 ▸ 记忆"页里的"Delta 的建议"。接受（可改写）后才写入 `memories`，并保留候选的来源；拒绝后同样的文字不再被提出。
- 任何一处决定后，另一处不再重复询问：建议卡会先向存储确认候选是否仍在等待。
- 不做自动保存；本版本没有任何不经用户确认的写入路径。

### 2. 默认关闭，关闭时模型看不到这个工具

- 记忆开关默认关闭（原先配置文件缺省按"开"读取，现改为缺省"关"，与"开关不可用、什么都不做"的现状一致）。
- 开关关闭时，`memory_propose` 不在该会话提供给模型的工具里（`tool_surface`），系统提示词里对应的一段也不出现；存储层另有一道检查，关闭时拒绝新增候选。读不出设置文件按关闭处理。
- 建议的数量受限：一次最多 30 条等待决定；每条不超过 500 字；与已保存、已在等待、已被拒绝的完全相同的建议不再入表。

### 3. 带来源，纠正保留历史

- 每条记忆记录来源、保存方式（`user` 用户自己写、`candidate` 建议后接受、`import` 导入）。
- 修改一条记忆时新建一行，旧行标记 `superseded` 并指向新行，旧措辞作为历史保留在本机。
- 删除一条记忆会连同它被替代过的所有旧版本一起清除；"全部忘记"清空记忆与候选。记忆页的说明如实写出这一点。
- 导出文件仍是 `delta.memory` 版本 1，只含当前有效的记忆，旧版导入保持可读。表结构用 `ALTER` 增列演进，旧库原样打开。

### 4. 缓存约束（给后续步骤）

模型要看到记忆时，注入内容必须像"当前时间"那样附在最新消息上，**不得写进系统提示词或工具定义**，否则每次记忆变化都会让缓存前缀失效。

## 后续步骤（本 ADR 尚未实现）

以下来自原草案，仍是方向，没有在本步骤实现，也没有对应代码：

1. **按需注入。** 每轮只检索少量相关条目，设上限；单独标注为"用户保存的记忆"，带记忆编号与来源；来源变化时标记"可能过时"；按工作区划分范围；用户开启后才生效。
2. **注入可见。** 对话记录中以可展开的标记显示每条被使用的记忆，可对单条选择"这次不用"。账本记录每轮注入的记忆编号，不记内容（与 ADR-0086 一致）。
3. **暂停某条记忆但不删除**（撤回）。当前没有这个操作：没有界面能看到被撤回的条目，留一个不可见的状态比直接删除更不透明，所以等到注入存在、"暂停"有实际意义时再加。
4. **本地嵌入模型。** 本地运行的嵌入不算外发；远程嵌入属于外发，必须经过出境网关。是否需要、选哪个模型、对安装包体积的影响，等关键词检索有人用了再定。
5. **账本记录。** 接受、拒绝、删除目前不写账本；注入存在后一并补上。

## 不做

- 不集成外部记忆服务，不引入图结构的自动建图，不改为 Markdown 为唯一事实源。
- 不做自动保存；不把记忆用于修改策略、审批或权限。

## 后果

- 默认关闭时没有任何变化：工具不提供，请求体与缓存前缀与现在相同。
- 开启后每个会话多一个工具定义（不到 1 KB）和一段提示词；模型每次最多建议一条，用户逐条决定。
- 第一步本身还不会让模型"记得"什么。它的价值是先验证用户愿不愿意用、确认交互顺不顺手，以及候选的质量。若建议大多被拒绝，应先改提示词再做注入。

## 验证

- `memory.rs` 单元测试：候选在接受前不是记忆、接受时可改写、关闭时拒绝入表、被拒绝的不再提出、重复建议不重复入表、长度与数量上限、纠正保留历史且保留来源、删除清除旧版本、全部忘记清空候选、旧版数据库原样打开；工具经能力运行器调用时用本次运行作为来源。
- `tool_surface` 与控制面测试：开关决定是否提供 `memory_propose`。
- 端到端（模拟运行时）：开关默认关；记忆页与对话里的建议卡可接受、修改、拒绝；接受后可撤销；已在别处决定的建议不再出现。
- **未验证**：没有用真实模型验证它是否会在合适的时机提出合适的建议、是否会过度提出；提示词措辞按设计编写，需要用 beta 包观察实际建议的质量。Tauri 外壳本环境未能完整编译，新增的四个命令与已有记忆命令写法一致，需在打包后确认。
