# ADR-0075：会话内容可搜索（复用本地全文索引）

状态：**已接受**（所有者，2026-10-26，同意按建议执行）。

## 背景

- 现状（已核对）：本地资料库（ADR-0067）的全文索引只覆盖用户指定的文件夹；会话以 `<state>/conversations/<id>.jsonl` 保存，被有意排除在外。会话列表没有查询参数。因此用户无法搜索过去的对话内容。

## 决定

1. **复用现有 FTS5 技术，但独立存放。** 会话索引写入资料库同一个数据库的新表，不混入 `roots`/`files` 表（那两张表的语义是文件路径）。不引入新依赖，不做向量检索。
2. **两个入口。** 模型可调用的工具 `conversation_search`（返回会话编号、标题、时间、命中片段）；桌面端会话列表的搜索框（前端实现另行排期）。
3. **默认范围为当前工作区。** 跨工作区搜索不做。若将来需要，单独决定。这与"数据按工作区隔离"的硬约束一致。
4. **索引内容。** 只索引用户消息与助手的文本回复。工具的原始输出不入索引，以控制体积，也避免把工具输出中的大段内容变成可检索的记忆。
5. **同步。** 会话新增消息时增量更新；删除会话时同步删除其索引条目；会话改名不需要重建索引。
6. **隐私。** 索引只在本机。搜索结果作为工具结果进入模型请求时，受工作区出境档位约束（ADR-0057、ADR-0061），与其他工具结果相同。

## 不做

- 向量（语义）检索；
- 跨工作区检索；
- 索引工具原始输出。

## 未验证事项

- 大量会话下的索引体积与查询延迟尚未测量。
- 桌面端搜索框尚未实现。

## 实现记录

- 索引模块 `conversation_search.rs`：索引放在 `library.db` 中的独立表（`conversation_sources`、`conversation_messages` 与 `conversation_fts`），与资料库的 `roots`、`files` 表互不干扰。
- 增量更新：每条消息追加时同步该会话的新完整行（`append_session_message` 调用 `sync_session`）；搜索前执行一次补齐（`sync_all`），覆盖迁移前已存在的会话，并清除已不存在会话的索引。只读完整的行，正在写入的半行留到下次。
- 删除会话时同步删除索引（`delete_session` 调用 `remove_session`）；删除失败会出现在返回的警告中。
- 工具 `conversation_search`：只读，不需要审批；范围为调用会话所在的工作区，没有工作区的会话返回空结果并说明原因；结果按时间倒序，给出会话编号、标题、行号、角色和片段。
- 三个字以上的词使用 FTS5 trigram 索引，较短的词退化为子串扫描；多个词必须出现在同一条消息中。
- 未实现：桌面端会话列表的搜索框。跨工作区搜索不做。
- 未验证：大量会话下的索引体积与查询延迟未测量；未在真实会话文件上运行。
