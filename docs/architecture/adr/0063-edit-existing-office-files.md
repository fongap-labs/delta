# ADR-0063：编辑已有的 Office 文件（有边界的原地编辑）

状态：**提议**（实现按所有者 2026-10-25 对路线图任务 A1 的批准进行；本 ADR 待所有者确认后改为"已接受"）。

## 背景

ADR-0058 让 Foundation 能读取 PDF、DOCX、XLSX 与 PPTX，并能创建新的 Office 文件，但在"范围"一条中明确排除了原地编辑。结果是日常办公的闭环缺一环：用户让助手"把报告里的 Q3 改成 Q4"时，助手只能重新创建整份文件，原有的样式、编号、页眉、公式与图表都会丢失。

路线图把这一项列为办公闭环唯一的硬缺口。蓝图 2.1 仍然成立：Delta 不是 Office 套件，不复制 Word、Excel 与 PowerPoint 的编辑器能力。因此本 ADR 不放开"编辑"，只放开一个有边界的子集，并规定这个子集如何保证"除了被要求改的部分，其他都不变"。

## 决定

新增工具 `edit_document`，只做三类原子操作：

| 文件 | 操作 | 定位方式 |
|---|---|---|
| `.docx` | 在一个段落内替换文字（正文与表格） | `find` / `replace` |
| `.pptx` | 在一张幻灯片的一个段落内替换文字 | `slide`（与 `read_document` 的"slide N"一致）加 `find` / `replace` |
| `.xlsx` | 写入单元格或一个区域的值 | `sheet` 加 `cell` 或 `range` |

不做：版式与样式修改，插入或删除段落、行、幻灯片，图表、图片、宏、批注、修订，页眉页脚与备注的文字，PDF，以及旧的 `.doc`、`.xls`、`.ppt`。

### 1. 用文字定位，而不是用序号

`read_document` 返回的是"块"（DOCX 把约 3000 字的若干段落合成一块），块序号与段落序号并不对应，让模型自己推算段落序号很容易改错位置。所以文字类编辑用要找的文字定位：

- `find` 在整份文件里必须恰好出现一次，否则拒绝，并说明出现了几次；
- 需要时用 `occurrence`（从 1 开始的序号，或 `"all"`）明确选择；
- 一次匹配只在一个段落之内，不跨段落；
- `replace` 是一个段落的文字，不含换行。

### 2. 保真

- **文字片段（run）。** 一个短语常被格式变化切成几个 run。替换写入匹配开始处的那个 run，因此保留它的格式；后面 run 里被匹配的字符被删除，它们自己的格式保留。
- **逐字节复制。** 编辑后的文件由原文件重新打包：没有被改动的部件按原样复制（不重新压缩），被改动的部件按事件流重写，改动之外的元素和属性原样输出。
- **XLSX。** 只写被点名的单元格：已有单元格保留样式与其他属性，新单元格按列序、行序插入。文字写成内联字符串，因此不触碰其他单元格所指向的共享字符串表。以 `=` 开头的文字写成公式。合并单元格、其他公式、列宽、条件格式不变。被改动的行去掉可选的 `spans` 提示。

### 3. 回读校验，失败则整次拒绝

产出之前，把编辑后的文件读回来，与原文件比较：

- 部件集合相同；
- 被改动部件的段落数相同，不同的段落不多于被编辑触及的段落（DOCX、PPTX）；
- 工作表集合相同，没有被点名的行读出来与原来完全一致（XLSX）；
- 文件仍能被 `read_document` 的解析器读取。

任何一项不满足，整次编辑被拒绝，不产出文件。这与 ADR-0058 对 `create_document` 的校验是同一条原则：不因为模型的一句话就报告文件已改。

### 4. 审批、版本与网络

- 中风险，需要审批；副作用声明为 `local_write`。
- 编辑后的文件作为产出物暂存在同一个相对路径。运行时替换已有文件时，已经会把原件保存到 `.delta/versions/<run>/`（一次运行里第一次替换保留原件），界面的"恢复较早版本"可以取回，本决定不新增版本机制。
- 本工具只读写工作区内的文件，不发起任何网络请求，在 `private_only` 档位下同样可用。

### 5. 与 ADR-0058 的关系

本 ADR 修订 ADR-0058"使这些能力保持在蓝图范围之内的规则"第 1 条：把"不包括原地编辑"改为"原地编辑只包括 ADR-0063 规定的三类有边界的操作"。该条的其余内容（版式设计、宏、与 Office 兼容的编辑器仍不在范围内）与 ADR-0058 的其他各条不变。

## 后果

- 内置工具增加到 `edit_document`；`product_registry_owns_stable_model_tool_schemas` 同步更新。
- 系统提示词增加一句：修改已有文件用 `edit_document`，不要重新创建，先读后改并说明改了什么。
- 桌面端把 `edit_document` 当作写入类工具显示（步骤、审批卡片与"改动过的文件"）。
- 回归夹具：`projects/delta/crates/delta-core/tests/fixtures/office/` 下由 python-docx、openpyxl 与 python-pptx 生成的三个真实文件，覆盖默认模板、编号、页眉、表格、公式、合并单元格、条件格式与备注。

## 未验证事项

- 编辑后的文件用 python-docx、openpyxl 与 python-pptx 读回，并用 LibreOffice 转成 PDF 渲染过；**未用 Microsoft Office 或 WPS 打开**。
- 路线图要求每种格式 10 个真实样例；目前每种格式 1 到 2 个（DOCX 2 个、XLSX 2 个、PPTX 1 个）参与了真实文件验证，其中 3 个作为回归夹具提交，其余只用于一次性验证。
- 写入公式时不写缓存值。Excel 与 LibreOffice 在打开时会重新计算，其他读取器可能显示为空。
- 页眉、页脚、脚注、批注、修订以及幻灯片备注里的文字不会被改动，也无法用本工具修改。
