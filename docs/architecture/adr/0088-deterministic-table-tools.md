# ADR-0088：确定性的表格对账与台账核查

状态：**已采用**（2026-10-28，按所有者要求参考 DeepSeek Harness 社区插件中的表格对账类工具）。承接 ADR-0058（基础办公能力）、ADR-0078（统计不经过模型）。

## 背景

- 办公场景里常见的任务是：两张表对账、查发票台账里的重复、算错的金额和不可能的日期。`read_document` 能读出表格的文字，但对账与求和要靠模型"看着数"，既不可靠也不可复核。
- Delta 的一贯做法是：数字由工具算，模型只转述（统计不经过模型 ADR-0078，报告里的数字绑定到结果文件 ADR-0055）。表格对账应当同样如此。
- DeepSeek Harness 的社区插件目录里有同类工具：`dsh-table-ingest`（把表格转成结构化数据）、`dsh-excel-reconcile`（按键连接两张表并报告字段差异）、`dsh-invoice-ledger`（标出重复发票、算术错误、日期异常）。本 ADR 取其意，不取其实现：本仓库没有读到它们的源码，工具按 Delta 自己的合同重新设计。

## 决定

### 1. 两个只读的原生工具

| 工具 | 作用 |
|---|---|
| `table_reconcile` | 按一个或多个关键列把两张表对齐，报告只在左表的行、只在右表的行、重复的键、以及两边都有的行里不同的单元格（数字可设容差）。 |
| `table_check` | 检查一张表：按指定列重复的行、每行必须成立的算式（如 `amount = quantity * unit_price + tax`）、不是日期或超出范围的日期（默认不得晚于今天）、不得为空的列。 |

- 读取 CSV、TSV 与 XLSX（按工作表名选择，可指定表头所在行）。行号是文件自己的行号：CSV 按文件中的行（空行与带引号的换行都计入），XLSX 按工作表行号。
- 两个工具都是 `read` 类别、低风险、不需要审批、没有网络授权、不写任何文件。
- 键的比较：数字按数值比较（`001` 与 `1.0` 是同一个键），文本忽略大小写和空白。单元格的比较：数字在容差内相等，文本忽略多余空白但区分大小写。
- 数字按账本写法读取：千分位、货币符号、百分号、括号表示负数。日期支持 `2026-10-28`、`2026/10/28`、`2026.10.28`、`2026年10月28日`、`20261028` 与表格的日序号。
- 算式只支持列、数字、`+ - * /` 与括号，不能调用函数。标题里有空格的列用反引号括起。除以零、不是数字的单元格不算"算式成立"，会单独报告为 `not_a_number`。

### 2. 结果是计算出来的，不是估出来的

- 返回完整的计数（`counts`、`findings_total`）和最多 100 条明细；明细超过上限时计数仍然完整。
- 描述与提示词都要求模型原样转述计数，不重新数、不自己加总，并给出工具返回的行号。
- 引用的列、规则或表头不存在时报错，**不当作通过**。

### 3. 不做

- **不写文件。** 对账结果要交付时，由模型用现有的 `create_document` 生成；不新增写入路径。
- **不做模糊匹配。** 键不同就是不同；是否把"Acme Ltd"与"Acme Limited"当成同一家，由用户决定后改键再对。
- **不做跨币种、跨日历或税率推断。** 算式里要什么写什么。
- **不读旧格式 `.xls`。** 与 `read_document` 一致，提示另存为 `.xlsx`。

## 后果

- 默认提供的工具增加 2 个，提示词多一个仅在这些工具提供时出现的指引块。
- XLSX 读取器多返回一份按单元格拆好的行（`Sheet.rows`），原有按文字行的输出不变。

## 未验证事项

- 只用生成的样本文件和手写 CSV 测试，没有在真实企业的发票台账上抽样；真实文件里的合并单元格、公式未计算的单元格（显示为 `=公式`）、隐藏行列的处理需要抽样检查。
- 日期的 `日/月/年` 与 `月/日/年` 写法有歧义，当前不识别，会报告为"不是日期"。
