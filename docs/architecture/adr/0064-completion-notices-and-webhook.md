# ADR-0064：任务完成通知与可选 Webhook

状态：**提议**（实现按所有者 2026-10-25 对路线图任务 B5 的批准进行；待所有者确认后改为"已接受"）。

## 背景

路线图 B5 要求：完成后的本地摘要通知带产物链接；Inbox 审批队列按任务分组、批量批复（已完成，见 CHANGELOG）；可选的本地 Webhook，由用户配置 URL，并走出站判定。

撰写时的现状（已核对）：

1. 桌面端只在窗口隐藏时弹一条固定文字"任务已完成，点击查看结果"，点击不做任何事，不说结果是什么，也不说产生了什么文件。
2. 定时任务有 `notify_on_completion` 字段（默认 true），但没有任何代码读取它。
3. Inbox 有 `notice` 类条目，用于无人值守运行的提醒；它能带 `data`，但此前没有写入过。
4. 出站去向由 ADR-0057（模型请求）与 ADR-0061（工具调用）判定。Webhook 是一条新的出站路径，必须同样受判定约束。

## 决定

### 1. 本地通知

- 桌面通知写出回答的开头（去掉 Markdown 标记，最多 120 个字符）和本轮交付的文件名（最多三个，其余计数）。点击通知把窗口带到前台，并打开第一个文件。没有回答文字时仍用原来的固定句子。
- 文件来自运行时的 `artifact_updated` 事件：只计已定稿的产出物，草稿不计。
- 定时任务运行结束时，运行时在 Inbox 写一条 `notice`：标题"Finished: 任务名"，正文是回答的开头，`data.artifacts` 列出文件。Inbox 中每个文件一个按钮，点击打开该次运行的会话，并在其中打开文件。每次运行最多一条（以运行 ID 去重）。
- `notify_on_completion` 为 false 的任务既不写 Inbox 条目，也不发 Webhook。

### 2. Webhook

- 一个 URL，一份设置文件 `webhook.json`（状态目录，仅所有者可读写，与 `egress.json` 同法原子写入）。默认关闭。URL 必须是 http 或 https，必须有主机，不得含用户名或密码（否则会进入审计日志与设置页面）。
- 一轮正常结束后，运行时在独立线程里发一次 POST，不拖慢下一轮。
- **出站判定与模型请求相同**（ADR-0057 的 `decide_model_request`）：按工作区的出站档位和主机类别决定。允许才发；"每次询问"档位不发，因为 Webhook 没有可询问的人，原因写入审计日志；"仅私有"档位只发给本机或私有网络；"仅已批准端点"只发给私有或已批准的主机。尚未选择档位时不发。判定依赖地址的私有类别时，连接固定使用检查过的地址，防止解析被改写。
- 不跟随重定向（响应的 3xx 视为失败）。连接 5 秒、读取 10 秒超时。不重试。
- **默认只发最少内容**：事件名、会话 ID、来源（`chat` 或 `automation`）、完成时间和文件个数。用户在设置里打开"附带详情"后，才附带标题、回答开头（280 字符）和文件路径与名字（最多 20 个，个数仍给全）。
- **每次尝试都写审计日志**（工具名 `notification.webhook`，阶段 `sent`、`skipped` 或 `failed`，含主机、类别、档位与原因），**不写消息内容**。
- 设置页有"发送测试"：用默认档位判定，在 Webhook 关闭时也可以测，结果如实显示（已发送、被档位拒绝及原因、失败及原因）。

### 3. 不做

- 不做重试队列、签名头、自定义请求头与多个 URL。需要签名或鉴权的场景应经由用户自己的中转服务。
- 不通过代理发送（与模型请求一样，代理策略另议）。
- 不在聊天里通知"另一个会话完成"：Inbox 已有会话列表与徽标。

## 后果

- 新增 `webhook` 模块、运行时在回合正常结束处调用 `announce_completion`、`Inbox::add_notice_with_data`、`AutomationStore::completion_context`。
- 桌面端新增设置卡片（设置 ▸ 隐私）、Inbox 通知中的文件按钮和 Tauri 命令 `get_webhook_settings`、`set_webhook_settings`、`test_webhook`。
- 摘要是模型的回答，可能含敏感内容；只在用户打开"附带详情"后才会离开本机，并且仍受出站档位约束。

## 未验证事项

- Tauri 命令（`runtime_ipc.rs`、`lib.rs`）在本次开发环境无法编译（缺少 webkit2gtk 等系统库），仅按同文件中同类命令对照写成；核心逻辑在 `delta-core` 中并有测试。
- 桌面通知的点击行为在 Tauri 的 WebView 里是否被系统支持，未在真实桌面上验证；测试用的是替身 `Notification`。
- 只验证了发往本机的 Webhook 与被拒绝的情形；未对公网地址发过请求。
- 没有对 HTTPS 证书错误、很慢的服务器做专门测试（只测了拒绝连接与 3xx、5xx）。
- 工作区的出站档位是"每次询问"时，Webhook 不会发送（它无法询问用户），只会在审计日志里留一条 `skipped`。设置页只在点"发送测试"时才会显示这个结果；平时用户看不到"为什么没收到"。目前没有在界面里提示这一点。
