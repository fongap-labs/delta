# ADR-0077：关键路径性能预算与门禁（提议）

状态：**提议**（待所有者确认后改为"已接受"）。

## 背景

- 长会话卡顿、内存膨胀目前只能靠用户反馈发现。
- DeepSeek Harness 的做法是为关键路径设定时间与内存上限，并在 CI 中强制执行。
- 仓库顶层目录（`repository-layout.md`）中没有 `benchmarks/`。新增顶层目录属于架构变更，需要本 ADR 说明理由。

## 方案比较

| 方案 | 说明 | 问题 |
|---|---|---|
| A. 顶层 `benchmarks/` 目录 | 与参考做法一致 | 新增顶层目录，需要架构变更审批 |
| B. `crates/delta-core/benches/` | 放在核心的子目录，不新增顶层目录 | 基准需要专用框架，可能引入新依赖，需要供应链评估 |
| C. 普通的集成测试加时间上限 | 不引入依赖 | CI 机器性能波动大，容易误报 |

## 建议

先采用 **C** 作为起点，只针对可以在单元层面确定的指标（如某个查询的渲染次数、内存分配的上界），不对墙钟时间设门禁。等积累了基线数据后，再决定是否采用 A 或 B。

## 未决事项

- 关键路径的清单（会话打开、长对话流式渲染、Skill 执行）需要先确定。
- 上限数值需要在真实机器上测量后才能设定。
