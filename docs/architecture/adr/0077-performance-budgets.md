# ADR-0077：关键路径性能预算与门禁（提议）

状态：**已接受**（所有者，2026-10-26，同意按建议采用方案 C）。

## 背景

- 长会话卡顿、内存膨胀目前只能靠用户反馈发现。
- DeepSeek Harness 的做法是为关键路径设定时间与内存上限，并在 CI 中强制执行。
- 仓库顶层目录（`repository-layout.md`）中没有 `benchmarks/`。新增顶层目录属于架构变更，需要本 ADR 说明理由。

## 方案比较

| 方案 | 说明 | 问题 |
|---|---|---|
| A. 顶层 `benchmarks/` 目录 | 与参考做法一致 | 新增顶层目录，需要架构变更审批 |
| B. `projects/delta/crates/delta-core/benches/` | 放在核心的子目录，不新增顶层目录 | 基准需要专用框架，可能引入新依赖，需要供应链评估 |
| C. 普通的集成测试加时间上限 | 不引入依赖 | CI 机器性能波动大，容易误报 |

## 建议

先采用 **C** 作为起点，只针对可以在单元层面确定的指标（如某个查询的渲染次数、内存分配的上界），不对墙钟时间设门禁。等积累了基线数据后，再决定是否采用 A 或 B。

## 未决事项

- 关键路径的清单（会话打开、长对话流式渲染、Skill 执行）需要先确定。
- 上限数值需要在真实机器上测量后才能设定。

## 决定

采用方案 C：不新增顶层目录，不引入基准框架，只用普通测试设定与单元层面可判定的上限。不对墙钟时间设门禁。

### 第一批已落地的上限

- 会话搜索单次最多返回 20 条命中，无论请求的 `limit` 多大（`conversation_search` 的 `MAX_LIMIT`，测试 `the_hit_count_is_capped_whatever_limit_is_asked`）。
- 桌面端搜索框最多显示 12 条命中（`SEARCH_HIT_LIMIT`）。
- 统计运行在启动前写入审计日志；审计不可写时拒绝运行（失败关闭），因此不会出现无记录的计算。

### 关键路径清单（待测量后设定数值）

1. 会话打开（`sessions_list`、`session_messages`）。
2. 长对话的流式渲染。
3. Skill 执行。

这三项的数值上限需要在真实机器上测量后才能设定，在此之前不设门禁。

## 未决事项

- 第 1 至第 3 项的数值上限（需要测量）。
- 何时考虑方案 A 或 B：待基线数据积累后再决定。
