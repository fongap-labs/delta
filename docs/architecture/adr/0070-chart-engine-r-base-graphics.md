# ADR-0070：图表由 R 基础绘图生成

状态：**已接受**（所有者，2026-10-26，同意方案 A 并拒绝把 Python 作为免费版必备运行时）。

## 背景

`data-analysis` 技能（ADR-0068）已要求在没有图表能力时如实说明。蓝图 §2.2 的研究分析与 §2.1 的日常办公都需要图表。现存情况（已核对）：

1. **没有图表块。** `create_document` 不支持图表（测试断言 `unknown block type: chart`），也不支持插图。
2. **可报告的数字由 R 计算**（ADR-0054）。Rust 通过 `find_rscript` 检查固定版本 R 4.6.0，并以 `Rscript --vanilla -e` 运行固定脚本，超时后强制结束（`statistics.rs`）。R 已是统计的必需依赖。
3. **桌面应用不随附 Python**（ADR-0058、`packaging/portable/build-portable.ps1`），ADR-0054 已经取消了为统计引入 Python 的中间层。
4. **溯源要求。** 报告中的数字可追溯到结果文件与其 SHA-256（ADR-0055）。图表若由另一套引擎生成，图与数字之间就有一个不受核对的环节。

## 方案比较

**A. R 基础绘图（选定方案的候选）。** 与统计共用 `find_rscript` 与 `run_rscript`，由 R 的 `png()` 设备输出图片。不引入任何 R 包。
- 优点：不新增运行时，不新增依赖；图与数字同源；可像结果文件一样记录哈希。
- 缺点：没有 R 就没有图；中文字体依赖系统配置，需要验证。

**B. Rust 原生生成 SVG。** 无外部依赖。
- 缺点：SVG 要转为 PNG 才能嵌入 DOCX 与 PPTX；`create_document` 目前不支持插图；转换需要光栅化库，按 ADR-0066 的做法必须先做许可证与供应链评估（`deny.toml`）。适合作为无 R 环境的后备，不作为首选。

**C. Python Worker（matplotlib）。** 功能与中文字体支持最好。
- 缺点：引入第二个计算运行时，与 ADR-0054 的方向相反；需要打包或要求用户安装。蓝图 §3.2 允许 Python 用于绘图，因此它可以作为可选的脚本路径，但不作为默认图表引擎。

## 决定

采用方案 A，新增工具 `chart_render`：

| 图 | 参数 | 对应技能的映射 |
|---|---|---|
| 直方图 | `path`、`column`、`bins`（可选，默认按 Sturges 规则） | 单数值列分布 |
| 箱线图 | `path`、`column`、`group` | 类别对比（数值按组） |
| 散点图 | `path`、`x`、`y`，可选 `fit: true` 画回归线 | 数值 vs 数值 |
| 柱状图 | `path`、`column`、`group`（各组均值） | 类别对比 |
| 折线图 | `path`、`x`（日期或顺序）、`y` | 时序与趋势 |

规则：

1. **输出。** 图片写入能力的暂存目录，由运行时登记为产出物（与 `statistics_record` 相同），路径为工作区内的 `.png`，经审批。
2. **溯源。** 同时写一个 `delta.figure` JSON 侧文件，记录输入文件 SHA-256、R 版本、脚本 SHA-256、图片 SHA-256 与绘图参数。数字（轴刻度除外）不进入报告，因此报告核对不受影响。
3. **不改变数据。** 输入只读，经 `resolve_read_path`，与统计工具相同。
4. **没有 R 时失败即关闭**，错误信息沿用 `statistics` 的写法，不回退到其他绘图方式。
5. **只用 `graphics` 包和 `grDevices`**，不安装任何 CRAN 包。
6. **不做的事。** 交互图、三维图、数据标签的自动排版、图表嵌入 DOCX 或 PPTX（需要单独的插图能力，见下文）。

## 后果

- 新增 `chart_render` 工具与一个固定的 R 脚本；`data-analysis` 技能可以把图表映射从"只说明"改为"实际生成"。
- 图片只能以独立文件交付。在 Markdown 报告里用 `![说明](路径)` 引用，不参与数字绑定。
- 嵌入 Office 文件需要 `create_document` 支持插图，属于另一个决定，本 ADR 不包含。

## 未验证事项

- **本开发环境没有安装 R**，所以脚本、`png()` 输出和哈希记录都没有实际运行过。
- **中文字体。** Windows 上 `png(type = "cairo")` 对 CJK 字体的支持取决于字体族配置；Linux 依赖 fontconfig。需要在 Windows 与 Linux 上各生成一张含中文标签的图片验证。这是本方案最大的风险。
- **Windows 的 `png()` 设备**在不同 R 版本间的默认行为可能不同，需要与 4.6.0 的固定版本一起测试。
- 图表的视觉质量只能人工检查，测试只能断言文件存在、非空、哈希一致。

## 实现记录

- `crates/delta-core/src/statistics/chart.rs`：工具 `chart_render`，能力 `chart.render`，经审批，副作用 `local_write`，注册在 `CapabilityHost::product_defaults`。
- R 程序 `CHART_SCRIPT` 编译进二进制，通过 `run_rscript` 运行，参数走命令行，列名与标题不拼进程序文本。
- 图片由 R 写入暂存目录，Rust 检查文件头为 PNG、计算哈希，并写入 `<chart_path>.figure.json`（`delta.figure`），两个文件都登记为产出物。
- 参数检查在启动 R 之前完成：图表类型、每种图需要的列、`bins` 范围、`fit` 类型、标题为单行且不超过 120 字，`chart_path` 必须是工作区内的相对 `.png` 路径。
- `data-analysis` 技能的图表限制改为"图表只能以独立 PNG 交付，不能插入 Word 或 Excel"，并加入图表映射。

## 未验证事项

- **本开发环境没有安装 R**：R 程序没有实际运行过；依赖 R 的测试在 `Rscript` 不存在时直接返回，因此它们通过并不代表绘图正确。需要在装有 R 4.6.0 的机器上运行一次 `chart_render` 的五种图。
- **中文字体**仍未验证。`png()` 使用默认字体族，中文标签很可能显示为方框；需要在 Windows 与 Linux 上各生成一张含中文标签的图。
- **日期判断**：`line` 把字符列解析为日期，只在所有非空值都能解析时启用；数值列直接当作数值。这一规则需要用真实数据检查。
- 图的视觉质量只能人工检查。
