# 公共合同治理

## 1. 权威边界

外部消费方只依赖公开合同。

### ❌ 错误做法 / 反面教材

直接调用核心内部实现。

```text
扩展 → 内部数据库与私有状态
```

### ✅ 正确做法 / 规范范例

通过稳定公开接口访问。

```text
扩展 → 公共能力合同 → 核心运行时
```

合同定义 Delta Foundation、Delta Suite 与外部扩展之间的稳定边界。

## 2. 合同范围

输入、输出、权限和状态均须明确。

### ❌ 错误做法 / 反面教材

仅声明接口名而不约束权限。

```text
Capability: execute()
```

### ✅ 正确做法 / 规范范例

按职责声明合同类别。

```text
Capability → 标识、输入、输出、权限
Worker     → 执行、状态、结果
Connector  → 外部集成边界
Artifact   → 身份、引用、来源证明
Event      → 事件、状态变更
```

## 3. 兼容性审查

破坏公共行为必须先审查消费方。

### ❌ 错误做法 / 反面教材

删除字段后直接发布。

```text
删除字段 → 不检查旧消费方
```

### ✅ 正确做法 / 规范范例

先核对依赖关系和迁移风险。

```text
消费方清查 → 行为对比 → 合同测试 → 审批与发布
```

增加可选字段和接口仍需检查兼容性；禁止在无证据时放宽权限或破坏旧会话恢复。

## 4. 扩展边界

扩展工具包不得暴露内部权威。

### ❌ 错误做法 / 反面教材

将核心写入权限直接交给扩展。

```text
SDK → 核心持久化内部实现
```

### ✅ 正确做法 / 规范范例

只提供受审查的公共访问能力。

```text
SDK → 合同访问 + 扩展接口 + 开发工具
```

机器读取合同和规则遵循中央工程语言要求；面向人的说明使用中文。**不建立语言例外登记。**
