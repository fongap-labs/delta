# 质量治理

## 1. 合并门禁

合并前必须完成确定性检查。

### ❌ 错误做法 / 反面教材

靠人工审查替代中央检查。

```text
人工审查通过 → 直接合并
```

### ✅ 正确做法 / 规范范例

中央状态和回归测试全部成功。

```text
安全检查 + 合同测试 + 回归验证 → validate-merge → 合并
```

`validate-merge` 名称保持稳定，不得通过重命名作业改变受保护状态。

## 2. 运行时测试

核心权威和公开接口必须回归验证。

### ❌ 错误做法 / 反面教材

用文件数量代替行为验收。

```text
减少 Python 文件 → 认定运行时迁移成功
```

### ✅ 正确做法 / 规范范例

按受影响能力运行测试。

```text
Rust 运行时 + 类型脚本接口 + 能力合同
           + 审批、取消、超时、崩溃、恢复
           → 合同与端到端测试
```

核心数据库只能由 Rust 权威写入；Worker 不得直接修改。测试仍包括格式、静态分析、布局、打包及必要的 Python 检查。

## 3. 研究与分析

数值结果必须可验证和复现。

### ❌ 错误做法 / 反面教材

仅凭模型解释确认结果。

```text
统计结果 → 模型称合理 → 通过
```

### ✅ 正确做法 / 规范范例

验证输入、方法、约束和输出。

```text
数据哈希 + 计算容差 + 设计矩阵 + 停止规则
         + 来源引用 + 报告文件 → 验收
```

涉及随机过程时固定可重现条件；研究报告不得以文本解释代替确定性计算。

## 4. 媒体与技能

成果必须存在且满足使用条件。

### ❌ 错误做法 / 反面教材

只验证工具返回成功。

```text
生成返回 200 → 宣称文件可用
```

### ✅ 正确做法 / 规范范例

验证文件及扩展的运行风险。

```text
文件格式 + 尺寸或时长 + 完整性 + 来源
        + 权限边界 + 资源限制 → 验收
```

学习成果上线前必须有回放、回归或用户采纳证据；不得自动降低审批、沙箱、网络或密钥边界。

## 5. 安全与依赖

敏感数据和高风险依赖不得放行。

### ❌ 错误做法 / 反面教材

提交真实凭据或忽略漏洞。

```text
Authorization: Bearer actual-secret
```

### ✅ 正确做法 / 规范范例

使用脱敏示例并审查依赖。

```text
Authorization: Bearer [REDACTED]
```

依赖检查覆盖漏洞、许可、破坏性变化、构建、沙箱与二进制再分发；详见 `DEPENDENCY_POLICY.md`。

## 6. 失败与回归

不得通过削弱检查掩盖失败。

### ❌ 错误做法 / 反面教材

删除测试或扩大忽略范围。

```text
测试失败 → skip / ignore → 合并
```

### ✅ 正确做法 / 规范范例

先定位归属，再修复并重测。

```text
本次变更 / 既存问题 / 环境 / 外部服务 / 工具链
        → 证据定位 → 修复 → 全部相关检查通过
```

出现环境故障时仍须保持失败结论，不因本地可运行而跳过中央门禁。

## 7. 发布验证

部署前后都必须验证真实产物。

### ❌ 错误做法 / 反面教材

把项目版本号当作部署证据。

```text
版本号一致 → 宣称部署成功
```

### ✅ 正确做法 / 规范范例

将部署标识与目标提交比对。

```text
构建与打包 → 安全检查 → 部署 → 健康状态与提交哈希核对
```

自动化验证提交身份，不推断或改写人工持有的发布编号。
