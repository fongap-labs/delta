[English](design-system.md) | 中文

## 令牌分层

- **基础令牌：** 原始色板与基础尺度，由主题包维护。功能样式不得直接使用 `--dsw-static-*`。
- **语义令牌：** 按用途命名的 `--dsw-alias-*`，在主题源码中分别映射浅色与深色主题。功能样式使用这些令牌，不复制颜色或主题分支。
- **组件或表面令牌：** `--dsw-specific-*` 用于现有语义令牌无法表达、且范围明确的组件约定。优先复用语义令牌和公共原语属性。
- **共享几何与排版：** 语义匹配时使用现有 `--dsw-radius-*`、`--dsw-font-*`、层级及主题尺度。仅属于单个组件且不是系统重复规格的几何值，可保留在对应 CSS Module。

新增令牌前，先搜索[令牌目录](design-token-catalog.zh.md)和主题样式表是否已有匹配语义。共享值只在其所属主题样式表中定义一次。组件覆盖必须有明确范围及回退值。不要建立第二套主题映射，也不要把令牌别名当作无关捷径。

`pnpm run verify-design-token-contract` 会检查令牌引用是否存在、共享名称是否仅由一个样式表拥有、全局定义是否位于 `ui-theme`、组件重绑定是否遵守明确例外、令牌引用是否无环，以及自动生成的目录是否与源码一致。新增或删除令牌名称后运行 `pnpm run generate-design-token-catalog`，并检查目录差异。

## 文案与术语

静态界面标签、操作、占位符、状态和错误文案均放在 locale 字典中，并通过类型化翻译器读取。共享产品术语放入共享 i18n 资源。动态值使用参数化消息，不要在组件内拼接翻译片段。用户输入、模型输出和外部内容仍属于数据，不应移入 locale 字典。

`verify-client-ui-i18n` 门禁检查功能界面源码中的硬编码文案；语言资源一致性与元数据由对应门禁检查。保留技术标识与第三方署名。遇到新增文案时，应补齐 locale 资源，不应放宽检查；只有能够证明内容并非界面文案时，才采用范围狭窄且有说明的例外。

## 组件与插件

多个功能包使用同类控件时，优先复用 `ui-primitives`。功能包可以增加行为和组合，但不应复制公共按钮、菜单、对话框、输入框、图标或焦点样式。插件在 Client UI 中运行时应使用相同令牌及导出的公共原语。Markdown、语法高亮和文件预览等专业呈现器，应在集成边界消费主题令牌，同时保留其专属语法或数据语义。

## 治理范围

现有专项测试分别治理颜色字面量、圆角、菜单材质、层级、焦点、悬停及相关交互。共享令牌契约是额外 CI 门禁，不替代这些专项测试。组件自身的几何、运行时测量、操作系统原生窗口行为、SVG 路径数据和外部输入值不会自动视为违规。例外应保持狭窄，在对应门禁旁说明归属与原因，避免按大目录或大类属性豁免。

本目录不宣称每个组件尺寸都已令牌化。日常改动遇到重复设计值时，应在不改变渲染结果的前提下，将其提升到现有共享尺度或定义范围清晰的令牌，并迁移相关使用方。本阶段不进行视觉改版。
