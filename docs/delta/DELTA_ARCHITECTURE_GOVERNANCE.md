# Delta 架构治理（草案）

> 状态：草案，供项目评审；不表示源码已导入、能力已实现或已通过验收。日期：2026-11-23。
>
> 定位：Delta 源于 Harness，但产品目标、数据和演进方向由 Delta 掌握；首版可正常使用，之后逐步演进，并能最终独立发展。

## 一、适用范围与权威

本文定义 Delta 的产品架构、模块边界和演进原则。跨仓库命名、权限、CI、合并与发布规则以 [Action-Worker 共用治理](https://github.com/fongap-labs/action-worker/blob/main/docs/01_SHARED_GOVERNANCE.md)及其机器合同、策略和规则为准，本文不复制或覆盖中央规则。首版是否合入以中央门禁及项目验收证据为准。

## 二、目标与原则

1. **首次可用**：首次进入 Delta 仓库的产品源码，已在仓库外完成批准范围内的裁剪、品牌、数据隔离及中英文整改；通过真实验证和中央门禁后才合入 main。
2. **源于上游，不受限于上游**：首版复用 Harness 成熟实现；是否吸收上游变化由 Delta 决定。保留原生身份是兼容手段，不是永久架构目标。
3. **模块化单体**：按能力划分职责，首版交付完整应用；不因形式上的模块化而提前拆服务或复制一套内核。
4. **渐进独立**：Delta 掌握产品行为、数据、扩展和发布；在有明确收益时逐项替换底层实现，并验证迁移、回退和兼容。
5. **隐私与边界**：默认本地优先；不默认上报产品行为或会话。用户配置的模型、官方认证、插件及其他联网行为分别列明。

首发目标为 Windows x64 便携版，目录为 `App/`、`Data/`、`Other/`；Harness 核心功能继续保留。DeepSeek 官方账号为可选功能，官方登录失败不阻断首发，但必须明确告知受限情况，不能影响不登录时的基本使用。CUA、浏览器操作、Forge、Worktree 和 LiveShare 是 Delta 首版应保留并验收的产品能力；不直接吸收 Harness 处于实验状态的功能实现。对两者重叠之处，评估已可用的非实验实现或开发 Delta 自有实现，不因排除上游实现而删除产品功能。沿用此前的主动启用原则。LiveShare 首版服务选用用户自托管 HTTPS/WSS Relay；默认只读、链接限时且可撤销。分享内容经过 Relay，首次使用与每次分享都必须明确提示 Relay 信任边界。

## 三、逻辑架构

```text
Delta Desktop / Delta CLI
           ↓
Delta 产品：品牌、配置、语言、交互、产品功能
           ↓
能力模块：智能体、模型、会话、工具与权限、插件、工作区
           ↓
具体实现：首版以裁剪后的 Harness 实现为主；可逐项替换
```

层次描述依赖职责，不要求首版新建对应的每个物理包。只在有具体使用者、需要隔离的变化及验证方式时建立 Delta 接口或适配；禁止无使用者的转发层和重复内核。上游原生包名、插件元数据和协议可为兼容而保留，是否修改应经契约及生态测试。

## 四、模块责任

| 能力 | Delta 拥有的责任 | 首版处理 |
|---|---|---|
| 产品与入口 | 用户体验、桌面和 CLI 身份、命令与设置 | 复用并调整必要的桌面、Host、CLI 和前端 |
| 智能体 | Delta 对外提供的任务执行行为 | 复用并验证上游实现 |
| 模型 | 用户配置、凭据处理、调用行为 | 保留批准的模型协议及必要鉴权 |
| 会话 | 数据目录、读写恢复、格式版本和迁移责任 | 复用实现，明确数据兼容与恢复 |
| 工具与权限 | 终端、文件、工具执行和授权行为 | 保留并实际验证允许、拒绝与取消 |
| 插件 | 安装来源、生命周期、兼容范围与风险告知 | 保留必要原生协议；不声称对未知插件全面兼容 |
| 工作区与配置 | 用户数据隔离、配置和进程环境 | 与同机 Harness 隔离，不静默迁移 |
| 语言 | 第一方中英界面和用户偏好 | 中文系统变体使用简体中文，其他默认英文；允许手动覆盖 |

### 语言与会话体验

必须区分**应用界面语言**与**会话回复语言**，不能用其中一个自动改写另一个：

- **应用界面语言**是应用设置中的全局偏好，首版支持简体中文和英文。系统默认语言为中文变体时默认简体中文，其他语言默认英文，用户可手动覆盖并持久化。会话窗口中的按钮、菜单、工具状态、命令提示、审批确认、错误和无障碍文字都属于应用界面，始终跟随此设置；即使用户在同一会话改用另一种语言，界面也不自动切换。
- **会话回复语言**影响 Agent 面向用户撰写的自然语言回复和任务说明。用户在当前请求中明确指定语言时优先遵从；否则跟随用户当前自然语言表达，并结合该会话上下文保持连贯。代码、引用、文件或外部服务原文不作为切换回复语言的唯一依据。混合语言或无法可靠判断时，延续该会话最近明确使用的回复语言；没有上下文时采用用户消息的主要自然语言。应用语言设置不强制模型用同一语言回答。
- **机器与 Agent 指令**包括协议标识、机器读取字段、稳定错误代码、工具 schema、系统指令及供 Agent 阅读的操作说明，统一使用英文。用户输入、文件内容、外部服务原文按原样保留，不因语言设置而自动翻译。需要同时面向机器和用户的消息应使用稳定英文代码及参数，并由界面按应用语言生成展示文字，不能通过翻译改变协议或审计含义。

切换应用语言只改变界面显示，不回译或改写已保存的用户消息、模型回复、文件或外部原文。动态错误须提供可理解的中英文提示并保留必要诊断信息。验收应覆盖中文界面配英文会话、英文界面配中文会话、会话中途切换用户语言、明确指定回复语言、应用语言切换与重启持久化，以及工具状态/确认/错误的界面语言。模型语言偏好以实际模型行为验证，不能保证外部模型每次遵循。

需要同时面向机器和用户的消息应使用稳定英文代码及参数，并由用户界面按当前语言生成展示文字，不能通过翻译改变协议或审计含义。动态错误须提供可理解的中英文提示并保留必要诊断信息。中英文验收覆盖语言切换、持久化、会话状态、命令结果和错误；模型语言偏好以实际模型行为验证，不能保证外部模型每次遵循。

模块间避免新增对其他模块内部文件、未声明服务和存储细节的散落依赖。能力边界涉及输入输出、错误、权限、数据格式或生命周期时，要写明版本及兼容范围；改变持久化格式需提供迁移与恢复验证。

## 五、仓库与来源

目录表达责任，具体路径遵循固定上游版本的真实工作区及构建关系；不因追求目录整齐而机械移动上游代码。Delta 自有代码与保留的上游代码须能通过来源清单、路径或包归属识别。允许保留必要原生名称，但不得借来源名义扩大治理豁免。

每次导入记录上游仓库和 SHA、裁剪策略与处理程序版本、Delta 修改清单、文件清单、依赖与许可、Delta 提交和测试证据。首次处理在 Delta 仓库之外完成；完整未经裁剪上游快照不得进入 Delta 仓库任何分支。

不得将 Harness 处于实验状态的功能实现直接吸收进入 Delta，包括相关装配和专属实现；识别依据包括上游声明、包元数据和实际用途，而非仅凭名字。公共依赖与核心能力的交集须单独分析、记录来源并寻找合适的非实验替代，不能把重命名实验代码当作替代。Delta 自有实现或其他非实验来源仍须经过许可、安全、兼容和真实功能验证，不自动等同成熟可靠。

## 六、首次导入与同步

首版流程：固定 SHA 和批准能力矩阵 → 仓库外计算依赖与动态装配 → 生成已裁剪候选 → 完成 Delta 化和仓库外预检 → 首次导入受控分支 → 对最终提交执行中央门禁和真实桌面验收 → 合入 main。

处理失败可调整规则、补丁或产品实现，再重新生成或验证；修复必须反馈至可重复处理方案。未知模块和依赖进入审核，不因构建失败自动加入。禁止能力的检查涵盖装配、源码、依赖、产物及代表性运行场景；测试证据不声称证明所有可能行为均已覆盖。

持续同步以旧上游 SHA、新上游 SHA 和当前 Delta 为输入，记录变化、Delta 补丁、冲突及部分吸收决定。不能自动确定的冲突须显式处理；失败时不更新已验收的上游基线。安全修复可通过受控补丁回植，不得永久忽略。

## 七、安全、插件与数据

Delta 第一方联网行为应列明触发条件、目的地、数据类别及用户控制。插件安装、执行脚本和启用分别评估并告知；是否隔离以真实机制为准，同权运行不称为沙箱。官方账号登录、模型请求、插件访问与未来 Delta Sync 是不同行为。首版不默认云同步。

应用、Host、CLI、子进程和 Electron userData 的路径及环境应整体隔离；不静默复用 Harness 凭据。会话、配置迁移需定义版本、备份、失败恢复及降级限制。密钥不得进入日志或同步数据。

便携版约定：`App/` 存放应用及其运行组件，`Data/` 存放 Delta 管理的用户数据，`Other/` 存放随发行包提供的其他必要资料；具体布局以打包验证为准。以程序所在位置解析便携根目录，不能依赖当前工作目录。必须验证复制到新路径后启动、保存与恢复；目录不可写、路径包含空格或非 ASCII 字符、多个实例并发访问时要有明确处理。操作系统或外部组件可能产生的缓存、凭据或配置需逐项核实，不预先承诺绝对零系统痕迹，也不得未经说明将 Delta 用户数据写回原 Harness 目录。

## 八、模块替换与架构变更

替换模块前，记录动机、现有消费者、协议及存储格式、兼容范围、迁移和回退方式；先建立覆盖主要行为的契约测试，再切换实现，最后移除无用依赖。涉及外部插件或账号协议时，增加代表性兼容验证。无需为了宣布独立而删除所有合法保留的上游来源代码；能否独立构建、修复和发布是实际标准。

重大变更应提供决策记录，说明问题、选项、依赖方向、数据及权限影响、兼容和回退。中央策略变更按其受信任流程处理；Delta 文档不能自行授予例外或削弱门禁。

## 九、首版验收

验收证据须绑定 Delta 最终提交、上游 SHA、策略版本与实际环境，至少覆盖来源与裁剪、便携启动、真实模型及工具、会话恢复、CLI、代表性插件、被排除的上游实验实现、CUA、浏览器操作、Forge、Worktree、LiveShare、首版平台、语言、网络行为、凭据、许可证和中央门禁。五项产品能力使用经核验的非实验上游来源、其他来源或 Delta 自有实现，在真实环境逐项验收；未完成不得声称通过。DeepSeek 官方登录受限不阻断首发。
