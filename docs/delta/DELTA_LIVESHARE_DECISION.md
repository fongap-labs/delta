# Delta LiveShare 首版方案决策

日期：2026-11-23
状态：服务方向已确认；协议和功能实现待完成；不代表功能可用或已验收。

## 已确认的决定

- 首版保留 LiveShare 产品能力，但不吸收 Harness 标为实验性的 LiveShare 实现。
- LiveShare 使用用户自托管 HTTPS/WSS Relay。用户在 Delta 中填写自己的 Relay 服务地址；Delta 不默认连接第三方中继。
- 分享默认只读。每个分享链接有明确的到期时间，并可由分享者提前撤销；到期或撤销后，已连接的查看端也须立即失去访问。
- Relay 只承担连接、网页/请求转发和分享授权。会话正文不写入 Relay 持久存储，不记录请求体；Relay 运维者仍能看到经其转发的数据，因此分享前要用直白语言说明信任边界。
- 首版先分享一个指定会话。查看端不获得模型密钥、Host 凭据、终端、文件写入、工具执行、插件管理、CUA、浏览器控制、Forge、Worktree 或其他会话的访问权。

## 身份与链接安全约定

首版的分享链接是持有者凭证：得到链接的人可以在失效前查看被分享的内容。分享者须在创建前确认目标会话和到期时间。链接使用至少 256 位密码学随机熵；持久化只保存链接凭证的不可逆摘要。页面应避免第三方资源，设置 `Referrer-Policy: no-referrer`，不得把长期凭证写入日志或分析事件。Relay 的 Owner 管理凭据独立于分享链接，存入 Delta 凭据管理设施；Relay 部署端负责安全初始化和轮换该凭据。

首版建议默认有效期 24 小时，不允许永久链接；设置中可选择更短期限。服务端每次请求和长连接都检查授权，到期或撤销时关闭该分享的连接并使凭证失效。若 Relay 暂时离线或授权状态无法确认，Host 不得继续接受新的分享访问。

## 组件与数据流

```text
Delta Desktop Host
  ├─ 本地保留会话、凭据和访问策略
  ├─ 按只读 allowlist 响应一个指定会话
  └─ 主动建立 WSS ───────────────┐
                                  ▼
用户自托管 HTTPS/WSS Relay ←── Viewer Browser
  ├─ 保存分享摘要、权限、到期和撤销状态
  ├─ 转发页面资源及受限请求，不保存正文
  └─ 用 HTTPS 提供限时分享链接
```

Relay 是受信任的传输边界，不能代替 Host 授权。Host 必须按当前分享记录创建非 owner Peer，并由既有 Gateway/`remoteAccess` 再次执行逐方法、逐资源的权限检查。客户端隐藏按钮仅改善体验，不能作为安全边界。

## 首版验证门槛

1. 部署文档可在用户自有 HTTPS 域名上启动和升级 Relay；未配置有效 TLS 时拒绝公网服务。
2. 有效链接只能读取指定会话允许展示的内容；猜测、过期、撤销、Relay 不可达和 Host 重启后未恢复授权时均拒绝。
3. 查看端不能提示 Agent、停止任务、上传附件、派生会话、改文件、调用 shell、插件、MCP、CUA、Browser 或其他未批准端点。
4. 撤销后现存 HTTP 请求、流和 WebSocket 均关闭；Host 侧立即拒绝已有 Peer 的后续调用。
5. 会话数据、分享令牌、Owner 凭据不会进入 Relay 正文日志、Delta 日志、崩溃报告、URL 查询参数或遥测。
6. 在真实 Windows x64 Delta Desktop 与独立 Relay 间完成创建、分享、查看、拒绝、撤销、到期和断线恢复验收。

服务方向已确认，但 Relay Owner 凭据初始化/轮换界面、具体 Relay API、应用内分享界面、Host 授权集成和真实端到端测试仍属于未完成工作。完成这些工作前不得把 LiveShare 标为已实现或首版可用。
